## The five questions

**1. What decision in this code would a generic implementation not have made?**

Withholding `newbie` rather than `history` in the confounding benchmark's failure demonstration (`src/confounded.py`). The first version tried reusing `recency`/`history` with one column dropped, and it didn't produce a clean failure: `recency`, still observed, was correlated enough with the same selection mechanism to partially self-correct, so the "broken" estimate wasn't actually badly broken (DML's CI still contained the true benchmark — reproduced in `notebooks/01_exploration.ipynb`, not just described). Switching to `newbie`, a covariate close to orthogonal to the others with a standalone effect on `visit` comparable in size to the treatment effect itself, is a decision that required noticing the first attempt had failed and diagnosing why, not a decision available from a template.

**2. What is the specific, unrounded number that proves it works?**

The confounding benchmark's variant 2: DML with `newbie` withheld gives an ATE of 0.09490164194835683, 95% CI [0.08718395326648076, 0.1026193306302329], against a true benchmark of 0.0601 (`reports/06_confounding_benchmark.md`). The confidence interval excludes the true benchmark entirely, not merely misses the point estimate. That is the number this whole project's central methodological claim rests on: DML corrects confounding it can see and does not correct confounding it cannot, demonstrated rather than asserted.

**3. What is the honest limitation, and is it stated?**

Several, all stated in `reports/causal_report.md`'s Section 9 rather than left for a reader to find: `spend` is right-censored at $499.00 for 12 customers (every spend-based number in this project is a lower bound, not an unbiased estimate); the confounding validation in Section 4 tests selection on named, engineered covariates and says nothing about whether an unobserved confounder exists in the real, unconfounded data; the learned three-arm policy's advantage over the simplest baseline is not statistically established on this eval set; the revenue-based targeting claim's confidence interval crosses zero. None of these are softened or buried in a closing paragraph; each has its own bullet with the specific number attached.

**4. What failed along the way, and is that visible?**

Visible in three places, not just this document. `notebooks/01_exploration.ipynb` reproduces the rejected confounding-withholding attempt live, with real output showing why it didn't work, immediately followed by the version that does. `CLAUDE.md`'s State log records real bugs caught during the build: the `build_covariate_matrix()` single-row column-mismatch bug found while building `src/persist.py`; the refuters silently testing the wrong (better-specified) model until `drop_cols` was added to `src/refute.py`; three real Streamlit bugs (a `starlette` 1.0 breaking change, a missing `sys.path` entry, a `$...$` LaTeX-span bug that silently ate two dollar amounts from a caption) found by actually testing the app in a browser rather than trusting that it imported cleanly; and a CI test (`test_render_pdf_raises_clearly_if_chrome_is_missing`) that passed locally but was silently testing nothing on GitHub's `ubuntu-latest` runner, caught by checking the actual CI run rather than assuming the local pass was sufficient.

**5. Can every line survive a hostile line-by-line interview?**

The two hardest sections to defend are the three-arm policy learner (`src/policy.py`) and the doubly-robust IPW value estimator scoring it, both flagged during planning as the parts of this build with the least margin for hand-waving. Both are defensible on the numbers already reported: the `DRPolicyForest` categories bug (alphabetical-first `Mens E-Mail` silently becoming the baseline instead of `No E-Mail`) was caught and fixed with a test asserting `email nobody` recovers the true control rate, not assumed correct; the IPW estimator's own sanity check (`email nobody` policy value 0.1061 vs the true control rate 0.1062) is in the report precisely so a reader can verify the scoring method isn't silently biased before trusting it on the more interesting comparisons. `reports/interview_qa.md` names the specific pushback each remaining honest limitation invites and answers it with a file and a number, not a hedge.
